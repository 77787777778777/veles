A fix release for long sessions on Anthropic routes, which were costing far
more than they should. Upgrading keeps your configuration: run the
installer again (Linux, Windows), or install the new APKs over the old
ones on Android (the userland first). The APKs are signed with the same
key as 0.1.3, so they upgrade in place.

## Fixed

- **Compaction never happened on Anthropic routes.** The compaction
  summary is a non-streaming request, and the Anthropic driver sent it
  with the plugin HTTP call's 30-second limit. A summary takes longer
  than that to write, so every attempt timed out and was logged as a
  502. The history was kept whole, and the next turn tried again: each
  turn waited 30 seconds for a summary that never came, then sent the
  full history anyway, which in one session was 500,000 tokens. The
  driver's non-streaming calls now get the 600 seconds the engine's own
  provider client allows.
- **A failed compaction is no longer retried at every turn.** After a
  failed summary, automatic compaction waits 2 minutes, then 4, 8, 16,
  and at most 30, before it tries again, and the transcript says once
  why it failed. `/compact` still runs at once, and when it fails it
  says why instead of "nothing to compact".
- **Long Anthropic sessions lost their prompt cache.**
  - The driver now asks for Anthropic's one-hour cache instead of the
    five-minute one. A tool loop on a frontier model can spend several
    minutes writing one answer and more running its tools, so the
    five-minute entry often expired before the next request, and each
    expiry wrote the whole conversation into the cache again. A
    one-hour write costs more per token, but a round only writes what
    it added. Set `cache_ttl = "5m"` on the provider entry to keep the
    old behaviour.
  - A memory write no longer rewrites the system prompt in the middle of
    a session. The rewrite changed the start of every later request, so
    the next one stored the whole conversation in the cache again. The
    note is still in the conversation, as the model's own tool call, and
    the system prompt picks it up at the next compaction or session.

## Upgrading

- If you copied `tcl-anthropic-driver` into your own plugins directory
  (`~/.config/veles/plugins/`, `%APPDATA%\veles\plugins\` on Windows),
  your copy takes precedence over the bundled one. Delete it to use the
  bundled driver, or replace it with the new
  `plugins/examples/tcl-anthropic-driver/plugin.tcl`.
- For plugin authors: `veles::http_post` takes an optional fifth
  argument, `timeout_secs` (1 to 900, default 30), and a provider driver
  receives `veles.timeout_secs` and `veles.cache_ttl` with each request.
  See "Endpoint knobs" in docs/plugins.md.
