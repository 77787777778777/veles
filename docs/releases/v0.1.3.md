A fix release for 0.1.2's Anthropic caching. Upgrading keeps your
configuration: run the installer again (Linux, Windows), or install the
new APKs over the old ones on Android (the userland first). The APKs are
signed with the same key as 0.1.2, so they upgrade in place.

## Fixed

- **On Anthropic routes, the status bar showed the prompt cache at
  hundreds of thousands of percent, and auto-compaction stopped
  working.** Anthropic reports the cached part of a prompt separately
  from the rest, and its `input_tokens` counts only what comes after the
  last cache breakpoint. The Anthropic driver passed that number on as
  the size of the whole prompt. Once 0.1.2 turned caching on, a cached
  26,000-token prompt was recorded as 2 tokens. The cache share was
  divided by that, and auto-compaction, which watches the size of the
  last prompt, never saw the context fill up. The driver now reports the
  whole prompt: the uncached part plus what was read from and written to
  the cache.

## Upgrading

- If you copied `tcl-anthropic-driver` into your own plugins directory
  (`~/.config/veles/plugins/`, `%APPDATA%\veles\plugins\` on Windows),
  your copy takes precedence over the bundled one. Delete it to use the
  bundled driver, or replace it with the new
  `plugins/examples/tcl-anthropic-driver/plugin.tcl`. A running gateway
  picks the change up without a restart.
- Usage already recorded keeps the old numbers, so an Anthropic session
  from 0.1.2 can still show an inflated cache share for the session as a
  whole. The per-call figure is right from the first new call.

## Known limitations

As in 0.1.1.
