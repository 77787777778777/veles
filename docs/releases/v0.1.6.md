A fix release for multi-hazard approval grants and responsive desktop
transcript completion.

## Fixed

- **Standing approvals remember the permission classes you select.** A
  command matching several hazards now asks for the grant scope and the
  eligible permission classes separately. Every eligible class starts
  checked; unchecking one keeps it out of both session and permanent
  grants. The engine accepts only exact keys offered by that call, and
  hard-trigger approvals remain one-time only. Deselecting every class
  deliberately remembers nothing and makes the approval once-only;
  legacy replies that omit the permission answer keep the checked
  defaults. Desktop, TUI and Telegram expose the selection; typed and
  legacy replies retain compatible behavior.
- **Guard notes stay where they happened.** The desktop no longer deletes
  and repaints notes during end-of-turn reconciliation. Rebuilt answer,
  reasoning and tool rows retain their order around those notes, including
  after a theme or source-view rebuild.
- **Transcript completion yields to the Tk event loop.** Final rows are
  painted incrementally instead of rebuilding a long turn in one callback.
  The finishing session briefly holds new sends so they cannot become a
  steer to a completed turn; other sessions remain usable. The 100-note
  widget fixture returns from turn completion in 5 ms in the focused run,
  with a queued timer still able to run. This is fixture evidence, not a
  guarantee for every transcript or a completed live deployment check.
- The two new desktop status messages have translations in all 47 desktop
  catalogs. Android version code is 7.

## Upgrading

Run the installer again on Linux or Windows, or install the new APKs over
the old ones on Android (userland first). Configuration and transcripts
are preserved. The desktop needs the new Tcl code loaded. Core approval
changes take effect after upgrading and restarting the gateway; the
desktop-only transcript change does not require a core restart on its own.

## Verification scope

Focused tests cover selected permission keys, explicit scope selection,
legacy typed replies, exact-once note placement, rebuild order, failed
turns, background-session finalization, and a queued-event responsiveness
check. Full release and platform results are recorded in `COVERAGE.md`.
The release workflow signs the portable artifacts with Sigstore. Android
APKs are signed separately with the existing release key, matching the
installed phone app.
