*veles 0.2.0, 2026-11-07.*

A feature release: sessions you can join and hand work between, turns
that survive a gateway restart, a permission review panel, interactive
task panels, a fleet view in Instances, extension authoring in the Dev
tab, a dedicated selection translator, opt-in Anthropic Message Threads,
and a browser tab bridge for Linux and Windows. It also carries the fixes from a
pre-release review of all of the above. Everything since 0.1.6 is listed
here.

## Sessions, joining and delegation

- **`/join` is a capability.** `/join` and `/leave` need `session-join`.
  The owner has it; anyone else only after `/grant <who> session-join`. A
  grantee can join only another person's session in the channel they are
  typing in, on the same network, never a DM. Their lines run with the
  lower of their rights and that session's, and their questions are asked
  of them only. The owner's `/join` displaces a grantee (one joiner per
  session). `/join a` finds `a`'s live conversation without a session id.
- **Replies go back where they belong.** Replies to joined lines, session
  mail and wake rows go out on the network the session's own person
  speaks on, so an IRC `/join` no longer answers in the desktop. A join
  inside the same channel posts each reply once.
- **Subagents sit under their parent** in the desktop sidebar and the
  Sessions window, beyond the first page of sessions and in both
  directions.
- **Agents know how to reach other sessions and nodes.** The prompt now
  describes `sessions` list/send/check. The new read-only `nodes` tool
  shows each node's capabilities, freshness, load and whether this node
  can reach it. `delegate_task backend='any'` (and `gpu`) counts the
  children it has already placed on each node until they finish, so a
  batch spreads over the pool instead of piling onto one machine.
  Placement accounts for reported core counts, disk IO pressure, the
  work each node reports, and a cached live authentication probe.

## Restart recovery and export

- **A desktop turn cut off by a gateway stop, crash or reboot continues**
  from its saved history when the gateway comes back. A saved final reply
  is delivered without another provider call, saved tool results are
  reused, and an action whose result was not saved is never repeated: the
  turn stops for your review instead. A queued message is not sent twice.
  If the provider is unreachable, the turn retries after 20 s, 60 s and
  300 s and again on the next start, and goes to review after six
  attempts. Connector, A2A, session-mail, cron, subagent, TUI, app and
  trigger turns are not resumed, and recovery is off on macOS.
- **`/export` works the same everywhere.** One exporter serves the
  `session_export` tool, `/export [md|json]` on the desktop, TUI and chat
  connectors, and the desktop's export button. Markdown includes tool
  calls, results, notes and reasoning; JSON is fully typed. Files are
  created new under the data directory's `exports/` (mode 0600 on unix,
  timestamped names), outside the media directory. On a chat connector
  the file stays on the gateway host and the reply says so.

## Approvals and permissions

- **Permission grants panel.** The desktop ACL window's Permission
  grants… lists global grants, the session grants of every live session
  (desktop, Telegram, IRC and other chats, labelled by surface) and the
  `[approvals] allowlist` entries from config.toml, read-only. It revokes
  the exact grant you select.
- **Multi-hazard approvals answer from any surface.** A single typed reply
  such as `2` or `deny` (IRC, Telegram text, `veles chat`, NDJSON) answers
  the scope and keeps every permission class checked; `2; <keys>`
  narrows it. Before, those approvals could not be answered by text and
  timed out to deny. On the desktop and Android, Return in the note box
  commits the dialog with the note.
- **Hard rules always reach a human.** No standing rule (allowlist,
  session or durable) clears a hard rule any more, including rows stored
  for one before 0.1.5.
- **A desktop answer the question did not offer is refused** and the
  question stays open (for example `always` where only once and deny were
  offered).

## Desktop and TUI

- **Task panel.** Bare `/shells` or `/monitors`, Ctrl+Shift+B, the menu
  or the palette opens a panel listing shells, monitors and subagents,
  with output, confirmed cancel, and Detach foreground, which turns the
  running foreground terminal command into a background shell.
  `/shells kill|output <id>` and `/monitors cancel <id>` with arguments
  reach the engine from the desktop. The TUI has the same browser (↑↓,
  Enter for detail, `c` cancel, `b` detach, `r` refresh, Esc), and it
  opens mid-turn.
- **No more stall on hovering the status bar.** Tooltip, scrollbar and
  editor bindings were appended on every poll or switch; after hours of
  uptime one hover ran thousands of handlers (seen as Usage taking a long
  time to open).
- **A turn that starts while the previous one is still being finalized in
  the desktop** (queued from another window, the phone, a TUI, `/queue`,
  or a wake) now waits for that transcript to finish painting, so it
  appears after the previous answer and keeps Stop enabled. (0.1.6 held
  only the local Send button.)
- **The context figure no longer waits behind a running turn.**
  `/api/sessions/:id/context` read under the store lock and answered in up
  to 4 s mid-turn on a loaded machine; it now reads beside it. Right after
  a compaction the status bar shows the context estimate instead of the
  pre-compaction count and a stale "(compaction due)" until the next
  provider call (`/context` JSON gains `last_call_fresh`).
- **Android no longer crashes at start with location granted** (Android
  12 and later). NMEA sentences use the current listener API.

## Instances: a fleet view

- The Instances tab lists every node in the cluster registry
  automatically, with a health dot (stale, failing, fresh, self), Probe,
  Forget node…, per-kind sync status, and explicit Sync now / Apply
  received for store, memory, config and vault. A node bound to a saved
  instance is marked "managed via <instance>", and Attach checks that the
  bound gateway really is that node. `/fleet list|sync|apply|forget`
  offers the same on the chat surfaces. Forget propagates through cluster
  gossip with a tombstone, so a peer does not immediately restore a
  forgotten node. Logs… returns a bounded, secret-redacted log tail;
  Metrics reports host and gateway measurements or names what is
  unavailable. Drift compares versions and configuration fingerprints
  without disclosing configuration values, Gossip now requests an
  immediate exchange, and optional fleet alerts report stale and
  recovered nodes once.
- **Reviewed fleet deployment (experimental).** Instances > Fleet deploy…
  builds a manifest from a signed release, checks each target's health
  and exact revision, stages a canary, restarts and verifies it, continues
  or rolls back, and journals every step; Abandon closes an operation
  that installed nothing. It has been tested only against a fake gateway
  and has not yet run on a real node, so treat it as a preview. Linux
  signed bundles only; not on Android.

## Dev tab: extensions first

- New extension scaffolds a Tcl plugin in the user plugin directory, with
  a guide and snippets for hooks, tools, services, override points and
  providers.
- The editor selects a language server by file type: Tcl, JavaScript and
  TypeScript, Rust, C, Racket and Common Lisp. Diagnostics, completion,
  hover, definitions, references, symbols, rename and folding use the
  selected server's own protocol and position encoding. Check runs the
  appropriate gateway-side syntax or compiler check. A missing server is
  reported with the program to install; an unavailable Lisp or Racket
  server is not a successful check.
- AI assist answers design questions, explains diagnostics, proposes a
  reviewed change set across an extension's files, or generates a new
  extension that is created only on apply. These are direct tool-free
  completions with outbound secret scanning. Server-side apply revalidates
  and applies a change set whole. A core file can instead be drafted as
  an extension.
- Contribute wraps one or more of your extensions into a branch, commit
  and pull request to veles under `plugins/examples/<name>/`, after
  syntax and type checks and an explicit preview; it never overwrites an
  upstream path without a second confirmation. Push and PR have been
  tested against a local repository, not against GitHub.
- A plugin that fails to load no longer stops the plugins after it from
  loading.

## Translation

- **Translate a selection with a dedicated model.** Right-click selected
  text (or F11) on the desktop, or `/translate [--to <language>] -- <text>`
  on any surface. It calls one configured translation route directly: no
  agent turn, tools, history or memory. The popup shows the route used
  and offers retry, a target switch and copy.
- Engine strings now follow the desktop translations into the engine
  catalogs.

## Providers and extensions

- **Anthropic Message Threads (opt-in beta).** A native Anthropic route
  with `message_threads = true` continues a server-side thread instead of
  resending the history; veles' own store stays authoritative and every
  failure falls back to a full request. No speed or size benefit is
  claimed (see Known limits).
- **Optional referral links** for Alibaba, Anthropic and Kimi in the CLI
  and desktop setup and in the install guide. They are labelled as
  referrals, never preselected and never fetched. API credits from the
  Anthropic referral are granted only if you buy Max or Ultra; veles does
  not support using that subscription as login or API authentication.
- **Provider drivers can be named exactly** (`tcl:<plugin>:<driver>`,
  `so:<plugin>:<driver>`), a replaced or shadowed driver or plugin is
  shown rather than silent, a user copy shadowing a bundled plugin is
  flagged, and `veles doctor --providers` says what to fix.
- Extension API **0.11**: an optional `version` in `plugin.toml`, the
  opt-in `thread` request for native Anthropic drivers, qualified driver
  names. Existing plugins need no change.

## Browser tab bridge

- A small Chrome/Firefox extension lets you hand one of your own tabs to
  the agent through the `browser_extension` tool: status, snapshot,
  click, fill and navigate by reference. Password, one-time-code, card
  and hidden fields report only whether they are filled. No arbitrary
  JavaScript, cookies or storage. Plan mode allows only status and
  snapshot. It works only from the owner's sessions on the machine that
  runs the browser. The source install and portable Windows zip carry
  the extension; native-host registration works on Linux and Windows,
  with an untested macOS installation path. See
  `browser-extension/README.md`.

## Other fixes

- An edited cron schedule takes effect at the edit; before, the job
  fired once more at its old time.
- The URL guard refuses more non-global IPv6 ranges: the RFC 8215
  local-use NAT64 prefix `64:ff9b:1::/48`, site-local `fec0::/10`,
  IPv4-compatible `::/96`, documentation `2001:db8::/32` and discard
  `100::/64`.
- Automatic alt text answers galleries forward-only in code, not only
  through its ledger: a gallery posted before gallery support first
  loaded is never captioned.
- Trigger rows that nothing would run (`action=command`, or `prompt` on a
  channel event) are refused when written. `generate_video` without a
  video route says that nothing was generated. The hidden, non-working
  `veles install serve` is gone.
- Development builds report the right source revision in `/api/health`
  after later edits and commits.
- Packaging homepages point to https://github.com/77787777778777/veles.
- The local gate (`scripts/precommit.sh`) also runs the public export
  check, so a private identifier cannot slip into a commit unnoticed.

## Upgrading

- Run the installer again on Linux or Windows, or install the new APKs
  over the old ones on Android (userland first). The Android version code
  is 8; the APKs keep the existing release certificate. Configuration and
  transcripts are preserved. Restart the gateway and reload the desktop.
- **Plugin SDK crates.** 0.2.0 crosses the `^0.1` boundary:
  `veles-plugin-sdk` and `veles-plugin-abi-sdk` now require their
  siblings at `"0.2"`. A Rust plugin built against the crates.io SDK
  moves its requirements to `0.2` when the 0.2 crates are published.
- **Extension API 0.11** (0.1.6 shipped 0.10): nothing to do.
- **`[translation]`** is optional. With no section, the translator uses
  the first `[[custom_providers]]` entry, in config order, that lists
  `deepseek-v4.1-flash-1017`. To pin it, or if that provider's
  entitlement is off:
  `[translation] provider = "<name>"`, `model = "<model>"`, and optionally
  `target_language`.
- **`session-join`**: nothing changes for the owner. Grant it explicitly
  to anyone else who should be able to `/join`.
- **Message Threads** stays off unless a route sets
  `message_threads = true`. `VELES_ANTHROPIC_MESSAGE_THREADS` now applies
  only to `https://api.anthropic.com` routes; other hosts need the route
  flag. With threads on, the driver spellings
  `tcl-anthropic-driver:anthropic-messages` and
  `anthropic-so:anthropic-messages` are rejected (they never resolved);
  use `anthropic-messages`, `tcl:tcl-anthropic-driver:anthropic-messages`
  or `so:anthropic-so:anthropic-messages`. Anthropic error text may now
  end with `[error_code: …]`.
- **Browser bridge**: run `veles browser-extension install`, then load
  `browser-extension/` unpacked in Chrome (Developer mode) or as a
  temporary add-on in Firefox (Developer Edition and Nightly can install
  it unsigned). Rerun `veles browser-extension install --overwrite` after
  moving veles or switching profile. It is not on the Chrome Web Store or
  addons.mozilla.org.
- **Exports** now land in `<data>/exports/veles-<session>-<UTC time>.{md,json}`,
  not under `/tmp` or the media directory.
- Existing trigger rows that never ran are not migrated; they keep
  logging "unsupported".
- Existing global grants keep the full-call note they were stored with;
  the panel shows it redacted and shortened.
- On a node already running 0.1.5 or 0.1.6, galleries posted before the
  first start of 0.2.0 that were never answered are not answered later.

## Known limits

These are tested automatically but not yet confirmed on a live system:

- No live Message Threads continuation has succeeded yet. Every live
  continue measured before this release failed and fell back to a full
  request because of a veles bug, now fixed; it has not been re-measured.
- Fleet deployment has not run on a real node. The fleet view has not
  been driven against the real multi-node fleet.
- Restart recovery has not been checked by a supervised restart of a live
  gateway, nor on Windows or Android.
- The task panel has not been driven on Android.
- Contribute's push and pull request have not run against GitHub.
- The browser bridge passed off-screen Chrome and Firefox tests on Linux
  and real Firefox and Edge tests on Windows. Everyday browser profiles,
  Chrome on Windows and macOS remain untested.
- `/join` grants, two-network IRC routing and subagent nesting after a
  restart are covered by tests only.
- All 46 desktop locales passed structural catalog and placeholder
  checks, including 366 engine strings. Machine translation still needs
  native-speaker review; it is not a fluency guarantee.
- Live delegation exercised every registered node. Real multi-node UI
  workflows and IRC session-join grants remain covered by tests only.

Platform and live results are recorded in `COVERAGE.md` as they come in.
