A fix release for approval decisions, URL fetching, cron schedules,
subagent launches, automatic alt text, and the desktop context display.
Upgrading keeps your configuration: run the installer again on Linux or
Windows, or install the new APKs over the old ones on Android (userland
first). The APKs use the same upload key as 0.1.4.

## Fixed

- **One approval no longer clears unrelated hazards in the same command.**
  Every matched trigger must be covered before a standing permission
  applies. Hard rules still require a human even when the auxiliary screen
  would allow the call, and a forged session/always answer for a hard rule
  becomes one-time approval rather than a durable grant. Audit records and
  approval hooks now include every matched trigger.
- **URL fetching refuses translated private addresses and reserved ranges.**
  NAT64 and 6to4 addresses are checked using their own embedded IPv4
  offsets, and the benchmarking and reserved IPv4 ranges are refused.
- **Cron patterns use the node's local wall clock**, like naïve ISO
  one-shots. Stored UTC slots remain until consumed; subsequent slots are
  computed locally. Daylight-saving transitions use Croner's local-time
  rules: 02:30 becomes 03:00 in New York's spring gap, and a repeated local
  time may use its second occurrence when the search crosses fall-back.
- **Subagents still start after a development rebuild.** On Linux the child
  uses the live `/proc/self/exe` image rather than a deleted executable path.
- **Automatic alt text recognizes galleries.** New gallery attachments use
  `items`, including a gallery inside a quote-with-media record. Images that
  already have alt text are left alone; missing descriptions are supplied
  only for newly processed events. There is no historical-gallery backfill.
- **The desktop and Android context figure uses the provider's last prompt
  count** against the real context window, rather than inflating a character
  estimate over the capped compaction budget. The near/due thresholds use
  the capped compaction bar. The number is the last completed call's input,
  not the in-flight turn's exact total.

## Upgrading

- A process-plugin reload loads the atproto gallery fix without a gateway
  restart. Core changes take effect after upgrading and restarting the
  gateway; the desktop Tcl must be reloaded for the status-bar fix.
- Existing cron jobs keep their stored next UTC slot until it fires. No
  stored timestamps are migrated.
- The test matrix includes Linux and native Windows gates and real Tk status
  bar tests. A forward-only live gallery check against the designated test
  accounts is part of the deployment verification; it does not reprocess old
  galleries. A phone APK upgrade and a live desktop reload are separate
  runtime checks; building the release does not change a running gateway.

## Known limitations

The URL tests classify addresses; they are not a live NAT64/6to4 network
round trip. The last-call token count is necessarily behind the current
turn's input and output. See the release notes and open items for the
remaining verification work.
