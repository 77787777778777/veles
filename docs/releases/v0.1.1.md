A fix release for 0.1.0. Upgrading keeps your configuration: run the
installer again (Linux, Windows), or install the new APKs over the old
ones on Android (the userland first). The APKs are signed with the same
key as 0.1.0, so they upgrade in place.

## Fixed

- **Android: the desktop app did not start.** Opening veles showed the
  gateway screen, or nothing: the desktop's startup script asked for a
  Tcl package (tcllib's uuid) that the APK does not carry, and Tk exited
  before a window appeared. The desktop no longer needs it, and a test
  now checks every package the desktop loads against what the APK ships.
- **Linux: `install.sh` failed at the end for a normal user.** The
  install itself succeeded, then the cleanup printed thousands of
  "Permission denied" lines, exited 1 and left about 1 GB of staging
  files behind. (The one-line installer on the main branch has had this
  fix since 0.1.0 was released.)
- **The plain REPL printed every reply twice** (`veles chat --plain`):
  once as it streamed and once more at the end. It now prints it once.

## Known limitations

As in 0.1.0, plus:

- In a pool, a node that applies a large backlog of memory offers at
  once (for example after a long time offline, or after `veles
  recover`) can offer old versions of other nodes' memory files back to
  them. They arrive as sync questions; answer "keep" to each.
