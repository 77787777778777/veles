A fix release for 0.1.1: prompt caching on Anthropic now works, the
Anthropic driver ships with veles, and the desktop's Preview stops
reopening old pages. Upgrading keeps your configuration: run the
installer again (Linux, Windows), or install the new APKs over the old
ones on Android (the userland first). The APKs are signed with the same
key as 0.1.1, so they upgrade in place.

## Fixed

- **Anthropic prompts were not cached, or stopped being cached
  mid-turn.** Anthropic caches only where a request marks a cache
  breakpoint, and three things kept that from happening:
  - The default `cache_mode = "auto"` sent no breakpoints anywhere.
    `auto` now sends them on the routes that need them: the
    `anthropic-messages` driver, and OpenRouter's `anthropic/` models.
    Every other provider caches on its own and gets nothing new.
  - The one breakpoint in the conversation sat before your last
    message. Inside a long tool loop it never moved, so every round
    re-sent the turn so far uncached. Breakpoints now follow the
    conversation: each request reads exactly what the one before it
    wrote.
  - A breakpoint on a tool result never reached Anthropic. After the
    first steer or background-shell notice in a turn, only the system
    prompt was cached for the rest of it, and the model saw that tool
    result wrapped in JSON. Both versions of the driver now carry it.
- **A message whose text is a JSON list was dropped** by the Anthropic
  driver (for example, a pasted `["a", "b"]`). It now reaches the model
  as the text it was.
- **The desktop's Preview reopened the last previewed page on every
  start,** from any session, however old, and opened your browser on it
  if it was a URL. A preview now belongs to the session that opened it
  and is restored only while it is recent.

## Changed

- **The setup wizard's Anthropic choice uses Anthropic's own API**
  (`api_mode = "plugin"`, `driver = "anthropic-messages"`) instead of
  its OpenAI-compatible endpoint, which does not support prompt caching
  or return the model's thinking. The driver now ships with veles, so
  nothing has to be installed by hand. An existing entry keeps working
  as it is, without caching, and setup does not rewrite it. To switch
  it, edit it in `config.toml`: `base_url = "https://api.anthropic.com"`,
  `api_mode = "plugin"`, `driver = "anthropic-messages"`.

## Upgrading

- If you copied `tcl-anthropic-driver` into your own plugins directory
  (`~/.config/veles/plugins/`, `%APPDATA%\veles\plugins\` on Windows),
  your copy takes precedence over the bundled one. Delete it to use the
  bundled driver, or replace it with the new
  `plugins/examples/tcl-anthropic-driver/plugin.tcl`.
- If you set `cache_mode = "explicit"` on an Anthropic route to work
  around the first bug, you can leave it or remove it; `auto` now does
  the same.
