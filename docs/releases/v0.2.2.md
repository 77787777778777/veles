*veles 0.2.2, 2026-11-11.*

An errata release. 0.2.0 and 0.2.1 were published without an independent
review, and a read-through of the code (83 findings) and a drive of the real
desktop against clustered scratch gateways (25 more) found defects that the
gate does not catch, several in the features those releases announced. 0.2.2
fixes them and corrects what the 0.2.0 notes and the README said that the code
did not do.

## Fixes

Ids in parentheses are the audit's (`docs/issues/open-items/release-0.2.2.md`).

### Pool and delegation

- `delegate_task backend='any'` or `'gpu'` no longer keeps choosing a peer
  that stopped or rotated its token: a failed dial or gossip exchange is
  recorded at once, the child goes to the next node, and the answer names both
  hops (COMP-1, COMP-11).
- Two nodes placing at the same time now spread out: a change to a node's
  own work is gossiped within about a second, at most once per 5 s and wider on
  a busy disk (COMP-9, COMP-10).
- Automatic tool homes try a peer whose auth probe failed last, and a re-homed
  tool call now counts on the node that runs it (COMP-12).
- A placement claim or a served tool run whose release failed is pruned by age
  instead of counting until the gateway restarts (COMP-5); a peer can no longer
  hide this node's children in its report or count them under another node
  (COMP-6); a gossiped heartbeat from a clock running ahead is held to now
  (COMP-4).
- Placement lookups no longer block the async runtime on a busy `state.db`
  (COMP-7).
- The agent is told what a part sent to another node can reach: none of this
  node's files, and the peer's User level in its own sandbox; what is worth
  sending; and that a batch holds 3 parts (use background children for more)
  (COMP-2, COMP-13). The README said disk IO is not measured; it is, and the
  README now says so (COMP-8).
- Subagents placed on another node appear under their parent in the sidebar and
  the Sessions window of the node that placed them (ASK-2). A peer's rows nest
  under a local session only if that session placed a child on that node.
- A peer that rejects a delegated task now shows its own reason in the route cache
  and in `nodes` (lockdown, turn cap, `task_peers`), not always "task_peers does
  not name this node".
- The heartbeat's early publishes are spaced from the end of the last publish, so
  slow gossip no longer makes them back-to-back.

### Replay, compaction and web tools

- Sessions whose model reuses tool-call ids (for example `terminal:0` in every
  round) or whose route sends none no longer lose tool results or get a provider
  400 on every turn: results are paired with their calls by position on every
  wire (ENG-1).
- A tool round cut short after some of its calls keeps its answered calls; each
  call with no saved result is named in a separate engine note, which reads the
  same after a reload and is no longer written into the assistant's own message
  (ENG-3, ENG-7). The OpenAI Responses route gets the same repair (ENG-4).
- Compaction archives every summarized message again; 0.2.0 and 0.2.1 could
  leave one live, where it came back after the summary on every reload (ENG-2).
- `web_extract` through Tor: a slow page gets its full budget on the retry
  circuit, and a URL-guard refusal (SSRF, DNS, bad URL, redirect policy) is no
  longer fetched a second time (ENG-5, ENG-6).
- The Anthropic drivers (native and Tcl) accept histories with empty, repeated
  or colon-bearing tool ids from other routes (ENG-1).
- Config hot reload keeps working after `config.toml` has been replaced by
  veles' own settings writes, `sed -i` or an editor; before, later hand edits
  were ignored until a restart (SMOKE-25).

### Sessions, export and approvals

- After a gateway restart, a desktop turn cut during a read-only tool call or
  during the agent's own gateway restart continues without you; anything with
  side effects (a build or test run included) still waits for review, and no
  prompt is sent twice (ASK-3).
- Desktop `/join <name>` works like the chat surfaces (name, id prefix or id),
  and refusals read as sentences instead of JSON (ASK-1, SMOKE-20). Desktop
  `/export` takes md, markdown or json in any case and refuses anything else
  instead of silently writing Markdown (ASK-6, SMOKE-24). Export works on a
  replica (remote) session in the sidebar (ASK-5).
- A grantee whose session-join was withdrawn can still `/leave` (ASK-4).
- Registering a reserved hook that never fires now says so (ASK-8).
- TUI: multi-line command answers keep their line breaks, `/fleet sync` and
  `/fleet apply` answer in words, and an unknown `/command` is refused instead of
  being sent to the model as chat (SMOKE-19, SMOKE-20).
- Slash lines behave the same on the TUI, `veles chat` and the desktop: a path typed
  first is text, `//` sends a line that starts with a slash, and an unknown command
  says how to send the line as text.
- Restart recovery continues only this gateway's own restart; any other
  `veles gateway restart` (a binary that merely has that name) stops for review.
- Windows: restart recovery recognises the gateway's own restart as PowerShell and
  cmd write it, and plan mode no longer misreads a PowerShell line with a backslash
  before `;` as one command.
- Desktop: disabled buttons look disabled in every theme (SMOKE-11), and Cancel
  in the Running-tasks panel reports at once (SMOKE-14).

### Dev tab and extensions

- New extension keeps a multi-word purpose; before, any purpose with a space was
  dropped on the way to the gateway and Create then refused forever (DEV-1,
  SMOKE-3). The manifest keeps the purpose exactly as typed, quotes and
  backslashes included (DEV-10, SMOKE-13).
- The Dev editor can save an existing file again; every save used to be refused
  (SMOKE-1), and a save no longer overwrites a file that changed on the gateway
  after it was opened.
- A new TypeScript, Racket or Lisp extension is loaded through its own host at
  once, and the dialog says what the gateway answered ("Created and loaded", or
  "Created, not loaded" and why) instead of "Created and reloaded" for extensions
  left pending (SMOKE-2). A fresh install's first extension has hover and
  definition for the `::veles::` API and hot reload without a gateway restart
  (SMOKE-12).
- The editor toolbar wraps to the window, so Check, the path entry and pop-out are
  reachable at any size and on a phone; the editor gets the room (12 lines at
  1080x720 instead of 5) (SMOKE-8). Manager windows show their status line on its
  own row, so a long message no longer hides buttons (SMOKE-22). Manage extensions
  no longer marks every user extension "shadows bundled" (SMOKE-17).
- Author guide and API reference open in every build (AppImage, Windows zip,
  Android, nix package) and against a remote gateway: the gateway serves them
  (DEV-2).
- Check finds the shipped `tclsh` on Android and in the Windows zip, starts npm's
  `tsc.cmd` on Windows (Prepare used to fail with "Fix the failed syntax checks"),
  and reads a Racket or Lisp file with the engine the gateway runs when no `racket`
  or `ecl` program is installed (DEV-4, DEV-5, SMOKE-23).
- AI assist works on user extensions when the config directory sits behind a
  symlink (Android, a stow-managed `~/.config/veles`) (DEV-3), and its prompts carry
  every tier of the author guide, not the first 24,000 characters (DEV-9).
- Contribute: one PR takes up to 100 files per extension and 1000 in all, an opened
  PR frees its branch name and removes its prepared clone, and Prepare says when
  the gateway account has no git identity before cloning, with git's own message
  (DEV-8, SMOKE-18). The Windows git-hook test now runs and can fail (DEV-7).
- Opening or saving veles' own source in the Dev pane suggests writing an extension
  first (DEV-12).

### Browser tab bridge

- `browser_extension` is never re-homed to another node: a pool node without
  agent-browser no longer sends it to a peer (BX-1).
- The tool's request no longer carries the bridge's long-lived token; it carries a
  proof valid for one tab connection, and the endpoint file records the host pid,
  so a stale endpoint is not a connected tab (BX-3). A slow or silent caller on the
  loopback port can no longer hold the host (one 5 s deadline per request) (BX-4).
- Edge is registered on Linux and macOS as well, the source install ships the
  extension and an upgrade from source keeps the launcher and the loaded extension,
  and `veles browser-extension install` fails plainly if no extension directory is
  found (BX-2, BX-6). The browser e2e script now fails for a named browser that is
  missing instead of skipping it.

### Translation

- The translator's output is checked for lost placeholders and markup, and a
  warning is shown when something was lost; the selection can no longer forge the
  check's fence (TR-1).
- The Translate popup keeps every button on screen (including when no translator is
  configured), keeps the "No dedicated translator configured" guidance after a
  failed request, and Return retargets (SMOKE-9, TR-3).
- The i18n script gate counts words, not letters, and refuses English prose around
  kept names (TR-6).
- The translator's output check no longer raises false alarms for `%s` written as
  `%1$s` or for percent-encoded and decoded URLs, and a lost `%%` is caught.
- The Translate popup waits for the engine's budget (1200 s) instead of 10 s and
  says plainly when the translator did not answer.

### Languages

This release adds 100 interface strings (the command center, Dev tab and node
management) to all 46 languages. They are machine-translated with the dedicated
translation model; the structural checks pass (placeholders, key sets), but no
native speaker has reviewed them. Nine orphan keys were dropped, and the three
Yoruba rows that were wrong in 0.2.0 were redone.

### Fleet command center

- A restart requested from the command center is no longer counted toward `veles-gw`'s
  five-deaths give-up, and the fleet consistency verdict names an item a node lacks
  and reads "consistent with differences" instead of "consistent".
- Config sync keeps a node-only key written inside an inline table
  (`extra = { host = ... }`) on its node instead of sending it to peers.
- Fleet deploy, and Start, Stop and Restart of a saved instance that has a node id,
  first ask the instance's own gateway which node it is and refuse a mismatch,
  naming both ids. Before, a wrong or stale node id could stage, install and
  restart on another machine running the same release (FLEET-2). The proof covers
  the gateway link only: the restart goes to the saved ssh host, which nothing ties
  to that URL (see Known limits).
- Fleet deploy works from the Windows desktop; its journal no longer fails on
  Windows' missing file-permissions option (FLEET-1; tested with Windows semantics
  emulated on Linux, not driven on a Windows desktop).
- Forgetting a node fleet-wide: a receiving node removes only a node that is stale
  by its own threshold and never itself, a tombstone stamped ahead of its clock is
  held to now, tombstones older than 90 days are neither accepted nor passed on,
  and `veles nodes forget` refuses this node and a live node as the tab does
  (FLEET-4, FLEET-5, FLEET-6).
- A failed Probe no longer keeps a node "failing" until the next probe: the next
  good gossip exchange or sync pass clears it and the recovery is alerted (FLEET-3).
- The Instances detail pane says where health alerts go (sent from this gateway,
  by the gateway that runs the Telegram adapter, or not sent and why) and names a
  bound instance's ssh target (FLEET-8).
- `/fleet list` shows what the tab shows: failing nodes and why, per-kind sync
  status, inbox counts, version drift, forgotten nodes and alerts (owner only;
  other callers get the states); new verb `/fleet probe <node-id>` (FLEET-9).
- Windows nodes report memory, free disk, host uptime and a CPU busy share in
  Metrics, and send that busy share as their heartbeat load, so `any` placement no
  longer ranks an idle Windows node last; macOS nodes report memory and uptime
  (FLEET-7, COMP-3). Verified by unit tests on a Windows host; the macOS readers
  were type-checked only, and nothing was checked in a live tab or live placement.
- The Instances tab, as a person meets it (checked on three scratch gateways on
  Linux and by a booted-window test; not on a real Android build):
  every control (Start, Stop, Restart, Fleet deploy…, Add…, Edit…, Remove) wraps
  into rows at any window size and on a phone (SMOKE-4); every cluster node is on
  screen when you open the tab, which asks the gateway at once, and a node that
  went down while you were away reads stale (SMOKE-5, SMOKE-6); refreshes keep your
  open and closed groups, selection and scroll position (SMOKE-5); a config peer
  that is in sync reads "0 behind" (SMOKE-7); the Fleet deploy dialog shows all
  eight actions, its status line and Close, and the release tag starts as the
  version the attached gateway runs (SMOKE-10); the Add/Edit instance dialog is as
  wide as its fields (SMOKE-16); the Logs viewer opens at the start of each line
  (SMOKE-15); load has its own column, the detail no longer prints "null" or raw
  log records, and Apply received no longer pre-ticks a kind with nothing waiting
  (SMOKE-21).

### Records

- README: the browser bridge is Linux and Windows (never routed to another node),
  disk IO pressure is measured, restart recovery is verified on Linux only,
  desktop `/join` finds a session by name, and what a remote part can reach is said
  (REC-6, COMP-8, BX-5).
- The 0.2.0 notes' "Live delegation exercised every registered node" has no record
  behind it and was removed from the 0.2.0 notes; the 0.2.0 and 0.2.1 release
  records no longer claim deployments and verifications they did not make
  (REC-1, REC-10, REC-16).
- The v0.2.1 tag's `Cargo.lock` listed the workspace crates at 0.2.0 (fixed after
  the tag), so `cargo build --locked` of the 0.2.1 source fails (ENG-8).
- `THIRD_PARTY_LICENSES.md` in 0.2.0 and 0.2.1 was stale: the generated notices had
  not been regenerated since 0.1.0 (every veles crate listed as 0.1.0), because the
  notices script had been failing since a crate declared the OFL-1.1 license of the
  GNU Unifont it ships. 0.2.2 accepts OFL-1.1 and regenerates the file, with a
  section for the Tcl language server's crates.
- Pitfall number 105 was used three times; the numbering is repaired (REC-12).
- The gate now checks that every pitfall number is used once and that `Cargo.lock`
  matches the manifests (`--locked --offline`).

### Windows

- veles' own git runs in the plugins directory no longer leave a file-system monitor
  daemon that kept the data directory from being removed or renamed.

### Release mechanics

- A 0.2.1 desktop's installer fetched 0.2.0: its signed release URL and tag were not
  moved when 0.2.1 was cut. They now name this release.
- The 0.2.1 container image was labelled 0.2.0, because the image tag was not
  bumped; it follows the version now.
- 0.2.1 was never packaged for the distributions; the packaging now matches the
  release.
- The lockfile is committed with the version bump, so the tag builds with `--locked`.

## New

- A Tcl language server ships with the Linux packages. The nix package, the
  `.tar.zst` bundle and the AppImage (x86_64 and aarch64), and the gateway image
  built from the nix package, carry `tcl-lsp` (github.com/77787777778777/tcl-lsp,
  pinned in the flake), and the gateway starts that copy before one on `PATH`. The
  Dev tab's hover, go to definition, completion and diagnostics, Check and `/lint`
  work for Tcl extensions with nothing to build, and the Extension guide marks the
  server "ships with veles". The Windows zip and the Android APK do not include it;
  there the guide says so and where to get one (DEV-6). This corrects the 0.2.0
  notes, which listed Tcl among the editor's languages while no Tcl server shipped.

- `/approvals [revoke <rule>]` and `veles approvals [revoke <rule>]` review and
  revoke standing approval grants from the TUI, the REPL, the desktop composer, the
  chat surfaces and a shell (ASK-9).
- A bare `/join` lists the sessions you can join, on every surface (ASK-1).
- Extension load results: creating an extension reports what the gateway loaded
  and why not (SMOKE-2); New extension and Generate with AI can write an
  out-of-tree Rust plugin (a cdylib on `veles-plugin-abi-sdk` 0.2; build it with
  `cargo build --release`, then reload it in Manage extensions;
  `veles plugins new NAME --kind rust` writes the same crate) (DEV-12). The
  Extension guide lists which language servers the gateway actually has and how to
  get the missing ones (DEV-6).
- The translator's output check (TR-1).
- Compute placement, third round: early publish of a node's own work and tool homes
  that demote a refused peer (COMP-9, COMP-10).

### Fleet command center: managing the nodes

Run so far only on scratch Linux gateways on one laptop (2026-11-10), under
`veles-gw`. Not run on the real fleet, on a phone, on Windows or macOS, or through
a chat connector.

- Restart on a registry row restarts that node's gateway through whatever
  supervises it: a systemd unit whose `Restart=` covers a failed exit and whose main
  process the gateway is, the VPS container (its quadlet now declares
  `VELES_SUPERVISOR=container`; deploy that first or the VPS says it cannot restart
  itself), `veles-gw` or the Windows logon task, or the Android service. A node that
  knows no supervisor says so and stays up; the tab waits for the node to come back
  with a new boot. Live: a scratch gateway under `veles-gw` came back in 8 to 10 s,
  one without a supervisor refused. Not run: the VPS container, the laptop's user
  unit, the Windows task, Android.
- Config… reads and writes one key on one node under config sync's rules:
  node-local keys, credentials and held sections (`[acl]`, approvals, sandbox, hooks,
  plugins, MCP servers) are not written from another node, and a node whose owner
  reviews config takes no peer write at once.
- Probe all… and Sync all… (one kind) list their targets in one confirmation before
  running. Live: each ran on 2 of 2 nodes. There is no bulk forget.
- Every command-center action is recorded on the asking gateway (Audit log…,
  `/fleet audit`) and each answering node logs the request in its A2A audit log.
- Node health alerts also appear in the desktop window on every tab (polled every
  30 s) and as rows in the Instances list.
- Drift… says whether every node runs the same build, modules and plugins and flags
  the node that differs, including a user plugin that shadows a bundled one with
  other content. Live: a stale user copy of a plugin was flagged with both hashes.
- `/fleet` gains `status`, `restart`, `config get|set|unset`, `bulk probe|sync`,
  `alerts`, `forgotten` and `audit` (owner only; unit-tested, not run on a live
  chat surface).
- Node-to-node management uses its own JSON-RPC method (`veles/fleet-manage`).
  Nodes older than 0.2.2 refuse it cleanly. A change must be fresh (120 s window,
  never-seen request id) and name the boot or value it was decided on, so a replay
  is refused.

## Building and testing veles

- A bare `cargo test` on Linux keeps its scratch files in RAM (`.cargo/config.toml`
  runner, `scripts/cargo-test-runner.sh`): one crate's library tests took 68 minutes
  on disk and 157 seconds this way.
- The gate runs every test binary instead of stopping at the first red one, checks

## Known limits

- The Windows zip and the Android APK have no Tcl language server: Tcl gets
  highlighting and Check (the engine's own `tclsh`) there.
- An abandoned prepared contribution keeps its reservation and its clone under
  the data directory; pick another branch name.
- The browser bridge works only from your own sessions on the machine that runs
  the browser; remote sessions (Telegram, the VPS) cannot use it, by design. It
  takes one connection at a time and has no host authentication beyond the
  per-connection proof. Staying local-only is by design (the owner decided that a
  remotely reachable bridge is a bad idea), not a gap to be closed. The macOS paths were written and unit-tested but never run
  on a Mac; Edge on Linux is registered but was never run in a real Edge.
- A gateway stopped with SIGTERM waits for the delegate children it is running
  (up to `TimeoutStopSec` under systemd). A remote part sees none of the placing
  node's files, and there is no way to ship them.
- Restart recovery continues only a read-only tool call or the agent's own restart;
  other tool calls still go to review, and connector, A2A, cron, subagent, TUI and
  trigger turns are not resumed. It is verified on Linux; on Windows only its command recognition is covered by
  unit tests, and Android is not checked.
- TypeScript and JavaScript Check need `tsc` or `node` on the gateway. The Rust
  extension scaffold was compiled but never loaded into a gateway in this release's
  checks.
- The translator's warning text is English in every locale. New catalogs are
  machine-translated and unreviewed by native speakers.
- Children placed by earlier versions no longer nest under their parent in the
  session list. An older desktop reading the new "consistent with differences"
  verdict shows "Deployment consistency unknown". A 0.2.1 config-sync receiver still
  applies an old sender's whole-table row. Mixed fleets are otherwise as described
  under Upgrading.
- A joined-session view in the desktop still refuses `/` lines, and `chat -q` keeps
  its narrower refusal.
- A list of cosmetic rough edges found in the last desktop run is recorded in the
  release record (`docs/issues/open-items/release-0.2.2.md`, "Left open").
- Fleet management decisions are the owner's and still open: a held-section write
  (`[acl]`, approvals, sandbox, hooks, plugins, MCP servers) from the command center
  is refused rather than queued for the receiving owner; `[node.overrides]` is not
  written from a peer; Apply received does not pre-tick config, vault or memory
  when rows wait; and nothing ties a saved instance's ssh host to its proven
  gateway URL, so a right URL with a wrong host would restart another machine's unit.
- Restart over the cluster link needs the node to run under a supervisor veles
  knows; `/fleet list` from `veles chat` or the TUI shows only that process's view.
  Windows IO pressure is not measured.
- The desktop transcript still shows the last call's name for repeated tool-call
  ids.
- On Windows, plan mode's read-only list is still the POSIX one: under PowerShell or cmd
  it can let through a command that writes (`sort /O`, `date` setting the date, a
  redirect to `/dev/null`), so review a plan-mode command on Windows yourself.
- `/help` does not list `/leave` for someone without the session-join grant, although
  `/leave` works for them.

## Upgrading

- Upgrade every node. Mixed 0.2.0, 0.2.1 and 0.2.2 fleets work: nothing new on a
  wire breaks an older peer. Two protections hold fully only once every node is
  0.2.2: the clamp on a gossiped heartbeat from a clock running ahead (a 0.2.0 or
  0.2.1 relay keeps the future stamp alive, COMP-4), and the placement counts (a
  0.2.2 node counts re-homed tool runs in its children, and an older caller
  subtracts that unclamped, so it briefly under-counts its own unreported children).
- Run the installer again on Linux or Windows, or install the new APKs over the old
  ones on Android (userland first). The Android version code becomes 9; the APKs
  keep the existing release certificate (`apksigner` names the same signer for the
  published 0.2.1 APKs and the packages on the phone). Configuration and
  transcripts are preserved. Restart the gateway and reload the desktop.
- A user copy of a bundled plugin shadows the bundled one. If you copied the
  Anthropic driver (`tcl-anthropic-driver/plugin.tcl`) into your user plugin
  directory, replace it with the bundled driver, or the tool-id fix (ENG-1) does not
  reach your node; Manage extensions marks only copies that cover something.
